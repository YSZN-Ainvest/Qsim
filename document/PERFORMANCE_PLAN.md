## 结论

第一批优先解决**数据读取与对齐、日末统计组装、输出小文件开销**。保持Python＋NumPy＋PyArrow，不整体重写C++，也不把Numba默认列为第一步。

当前更接近A架构：按日加载行情，按bar顺序推进，单时点对股票截面向量化；每个信号时点计算因子和目标，账户顺序处理。不是先把整个历史的因子矩阵算完再回放账户。行情按日持有，所以“整年×股票×字段”的矩阵内存估算不能直接当作当前常驻内存；但滚动窗口、PIT状态及分钟Every的大量时点账户仍有成本。

## 对所提建议的取舍

| 建议 | QSim现状 | 判断 |
|---|---|---|
| 分阶段Profiling | 已有粗计时，尚有26.2%未细分 | 立即优先；补完整正常基准和细项 |
| Numba账户核 | NumPy状态更新已有；30分钟账户阶段占9.2% | 候选，先测1分钟；不先整块搬迁 |
| Rolling增量 | 每次compute将deque历史复制成矩阵，动量／反转仍检查整段有效性 | 长窗口／1分钟值得评估，优先减少复制和重复有效性检查；暂不贸然替换方差算法 |
| DAG缓存 | 已有命名因子依赖分层、相同基础因子和完全相同表达式的整项复用 | 保留；不是任意公式子树消除。重复operations及公共子表达式可作为后续候选 |
| 数据布局与对齐 | 每日8个字段分别pivot/reindex；bar切片是否连续需实测 | 第一批重点；复用证券／bar映射并减少重复转换，测试连续截面布局 |
| Polars Lazy Scan | 已使用PyArrow的投影／批读及PIT磁盘索引 | 先用现有栈优化；仅在对照能证明收益时增加Polars，不机械换库 |
| 多任务并行 | 已有因子线程池与独立配置进程池、共享输入缓存 | 已实现基础能力；改善共享读取后再调并发，避免先把NAS打满 |
| 行情与信号频率解耦 | signal_times已能只在选定时点算信号，历史仍逐bar更新 | 现有能力先用；不重复造开关，也不为提速改变用户的调仓时点 |
| C++重写 | 当前是bar级研究模拟，未做逐笔订单簿 | 不列入本轮；只有剩余确定热点且NumPy／Numba不够时考虑局部核 |

Numba的`fastmath`会放宽IEEE数值约束，本项目不以此换速度；保留float64。Polars的投影／谓词下推是有效机制，但QSim已有部分等价读取机制，能否更快须测量。[Numba性能说明](https://numba.readthedocs.io/en/stable/user/performance-tips.html)、[Polars优化说明](https://docs.pola.rs/user-guide/lazy/optimizations/)、[NumPy复制与视图](https://numpy.org/doc/stable/user/basics.copies.html)。

## 建议批准的第一批范围

### P0：建立可复现基准

1. 复现并解决剖析入口的ABI加载问题，统一正常CLI与测量脚本的解释器、启动环境和依赖加载。此前正常回测绘图成功，不能直接推断整个环境都不可用；不擅自升级主解释器或替换共享环境。
2. 拆分读取、因子原值、operations、分组／目标构建、账户、标签／统计、写入、绘图。阶段应互斥；嵌套计时单独说明，保留未归属时间，不重复计数。
3. 固定输入版本、股票池、因子、bar网格、账户数、费用、dump和线程。分别测30分钟及1分钟；先小规模试跑决定1分钟账户数和内存预算，不将30分钟结果直接外推。
4. 建立不带profiler的基准，至少3次交错A/B运行，报告中位数、范围、CPU时间、峰值RSS、读写量和文件数。cProfile只定位热点，不用于计算加速比。
5. 分开报告第一次构建缓存与复用缓存；不删除旧缓存或清空系统页缓存来制造“冷启动”。使用独立新缓存目录描述“应用缓存未建”，不宣称物理NAS也完全冷。

交付：阶段耗时表、热点调用表、可复用测量脚本和基线结果。没有完整基准，不进入大范围重构。

### P1：按基准逐项实施，不一次混改

| 改动包 | 拟修改内容 | 约束及风险 |
|---|---|---|
| 输入读取 | 减少缓存命中时不必要的锁／元数据操作；测试Arrow读取、必要列投影和直接Parquet路径；依据实测选择 | 保留原子构建、源版本校验、并发安全与PIT输入干预。不能靠复用未来特征提速，也不承诺去锁就是最大收益 |
| 对齐与布局 | 证券轴、bar轴映射一次，代替每个字段重复pivot/reindex；测试每个bar的证券截面连续 | 保持DayCube公共接口、缺失值、重复键检测、证券顺序和float64；任何布局调整需逐字段一致性对照 |
| 日末汇总 | 减少各时点账户重复建小DataFrame、分组和查询；尽可能同一日批量聚合 | Every仍保留独立账户，主结果均值不变；必须保持事件顺序、首末净资产、求和及NaN口径 |
| 输出 | 同一天同一表的多个账户／标签结果合并后写一次，减少小文件和重复目录操作；绘图只读必要列 | 每日／有界批落盘后释放，不攒全年；保留日志、失败分区、字段和行数。若改变分区文件数，需更新manifest和文档 |

每个包单独跑A/B并做数值检查；无收益或明显退化的改动不合入。不开启新的大规模异步写队列，不牺牲失败可诊断性，也不默认新增一套全量矩阵磁盘缓存。

## 第二批：第一批完成后再决定

2026-10-30追加范围：用户仅批准多因子中性化准备复用。已实现当期暴露／行业哑变量、相同有效掩码的标准化设计矩阵复用，仍逐因子lstsq；验证与局部基准见[性能验证](PERFORMANCE_RESULTS.md#多因子中性化准备复用2026-10-30)。以下长窗口、Numba和其他扩展未随本次实施。

- **长窗口与多因子**：检查每bar历史矩阵复制、重复窗口有效性扫描、相同原值重复operations。环形缓冲区与有效计数必须保存checkpoint状态；动量的“窗口内任一缺失即无效”语义不变。滚动标准差涉及数值稳定性，先保留现有算法作参考，再对长序列误差做专项验证。
- **公共子表达式**：仅在相同时间、数据版本、证券轴、有效截面和参数下复用。尤其rank/zscore/中性化不能跨不同股票池或不同共同有效截面盲目共享。QSim目前不是GP搜索引擎，本轮不扩成GP平台。
- **Numba**：仅提取剖析确认的纯数组热点，保留Python参考实现；`fastmath=False`、float64，不沿同一账户时间轴随意并行。首次编译与缓存后的运行分开计时，测试缺失值、涨跌停、T+1、资金、容量、费用和随机／checkpoint状态。
- **并行调度**：共享输入和单任务热点改善后，再测多个独立配置的吞吐；不增加用户已经明确不需要的StatsEvery时点账户并行，也不加入GPU／多机。

若仍保持30分钟样本中账户9.2%的占比，就算该阶段耗时完全消失，整次运行理论上也仅约1.10倍；这是该样本的上界估算，不适用于尚未测量的1分钟任务。必须依据新阶段占比再决定Numba投入。

## 验收与停止条件

- **正确性先行**：时间／证券／因子键、缺失与重复记录、分组归属、交易事件、标签状态保持一致。float64与既有alpha比较容差不变，不通过放宽容差制造PASS。
- **账户与统计**：对比连续日曲线、持仓、费用、PnL、每年及ALL汇总，包括dd_start/dd_end/winrate；逐日对账。CSV／Parquet的数据内容不应因分区布局优化而丢行或换顺序语义。
- **状态与因果性**：串并行对照、f/p/c、恢复新进程、跨日／跨周、1/5/30分钟、Every／Interval及Cohort兼容测试；新增状态必须纳入真实checkpoint。旧checkpoint若确需失效，明确版本边界，不暗中重算前缀。
- **性能目标而非承诺**：第一批以代表性分钟样本的暖缓存端到端中位耗时下降至少20%为目标；同时列出其他频率和冷构建成本。未达标先复盘，不能只展示某个函数的局部倍数。
- **内存与资源**：固定股票、窗口和账户数量，扩展天数验证峰值受控；记录RSS、文件页缓存、I/O和落盘文件数。以用户允许的合计500%CPU、启动前空闲内存60%为上限，仍依据实际剩余配额缩小，使用硬限制和持续监控。
- **保留可回退路径**：按小改动逐项验证，出现数值差异、内存增长、明显I/O放大或代表性任务退化时暂停对应包，先定位，不同时扩大改动范围。

已批准范围P0＋P1已完成；第二批仍需另行讨论。验收完成后统一留存，失败的改动单独撤回，不覆盖其他工作。
