# 负向买卖一档不平衡度示例

[返回 README](../README.md) · [配置](../configs/readme_30m_l1_4y.toml) · [外部数据接口](DATA.md)

特征在回测外预计算，QSim通过`kind="table"`读取。示例复用现有`level2_features`库的质量检查和`depth_imbalance_1_last`公式：

```text
(bid_volume_1 - ask_volume_1) / (bid_volume_1 + ask_volume_1)
```

原始Parquet仍保存上述正向值。当前回测配置在截尾、标准化后通过 `combine.expression = "-<l1_imbalance>"` 取负，沿用已有成品与索引。原始／处理后分量的dump仍为原方向，最终组合分数为负方向。

这是盘口挂单数量的不平衡度，不是主动买卖成交量或订单流不平衡度。分母为零时为空值；比例不依赖数量单位换算，不猜测逐笔成交方向编码。

## 时点与输入

- 使用2022–2025年已转换的原始quote Parquet、历史全A池、10分组；2021年没有对应正式Parquet，未用后来的数据补齐。
- 每天10:00、10:30、11:00、13:30、14:00、14:30决策，StatsEvery对应6套独立账户。行情网格仍为全天8根30分钟bar；主曲线是6套账户的比较均值。
- 调整`signal_times`时需同步生成那些时点的特征和缺失记录。不能直接增加9:30等本表没有的时点：QSim通用外部表默认沿用前值，9秒有效期由本例生成器检查，并不是回测框架自动为所有外部因子设置的过期规则。
- 每个时点`t`取严格早于`t`的最新快照，且快照年龄不超过9秒。不使用恰好在`t`的事件，不跨午休或隔夜沿用盘口。
- 最新快照若无效或存在无法确定顺序的同时间戳记录，值为空，不向前寻找一个更好看的有效快照。必要字段质量规则复用Level2库；不代表已认证供应商全部字段及完整性。
- 原始数据只有事件时间，`available_at=t`表示窗口完成时可用的假设，没有模拟接收／网络延迟。
- 本例明确映射`.SZ/.SH`到`.XSHE/.XSHG`；当前仅接入沪深，北交所`BJSE`因子为空、不参与分组。首尾源文件抽查只见SH／SZ，未完成北交所全历史接入核验。
- 每个日期、决策时点和证券均有一条记录。没有源文件、没有新快照或质量不通过时写NaN，覆盖外部表的旧值；已有持仓仍按QSim无新信号规则推进，不等于立即清仓。

输出为逐日Parquet，主键`(available_at, order_book_id)`，数值列`depth_imbalance_1_last`为float64。源文件日期缺口、有效值数量、拒绝数量、源大小和mtime保存在逐日audit JSON。

## 构建与验证

[构建脚本](../scripts/build_readme_l1_feature.py)按批读取必要字段，只保留各决策前9秒的候选快照；收齐不同batch／row group中的候选记录后统一检查重复时间戳并选择最新状态。这种读取方式只适用于本例的期末值，不能用于TWAP、成交量或其他需要完整窗口的统计。

先配置NAS缓存／临时目录和数值库单线程，核对可用资源及配额并设置cgroup硬限制，再运行。`--workers`是明确上限，不自动使用全部CPU；本次预算为最多5核／16GiB，其他服务器应按实际余量降低。

```bash
python scripts/build_readme_l1_feature.py \
  --library /home/qinml/level2_features \
  --start 2022-01-01 --end 2025-12-31 --workers 5 \
  --directory /mnt/nas/qinml_cache/qsim/result/readme_l1_2022_2025_20261030
```

日文件完成后原子发布；同样的命令可以跳过已经完成且源版本未变的日期。配置或构建代码变化时拒绝混用旧产物。等`COMPLETE.json`生成后，再运行[完整配置](../configs/readme_30m_l1_4y.toml)，不能把正在变化的目录用于正式回测或checkpoint验证。

[适配核验脚本](../scripts/verify_readme_l1_feature.py)将结果与Level2完整计算入口逐值比较，覆盖乱序、跨行组、重复时间戳、严格右边界、TTL、无效最新快照、证券映射和缺失日。另使用冻结的真实盘口样本执行QSim的f／p／c检查，验证外部因子读取和恢复；两类检查覆盖的层次不同。

历史盘口生成和QSim回测分别计时；扫描多年原始快照的耗时不能当作QSim一次回测的耗时。原始盘口只读，完整数据、审计和运行日志留NAS，Git只保存代码、配置、说明和结果图片。

## 本次产物与耗时

969个日分区，共34,529,346条时间／证券记录、26,232,674个有限值，约256.4 MiB。固定证券轴中不活跃、未接入或无有效快照的证券保留NaN；不能把所有NaN都解释为源数据损坏。16个日期缺少正式源文件，另有2023-12-08的13:30时点无有效快照；日期清单在`COMPLETE.json`和逐日audit中。

一次性生成耗时1小时45分，最多5核／16GiB、实际峰值14GiB、无swap；之后的QSim回测约20分42秒，其中首次PIT索引准备约175秒。本次负向回测复用成品与索引，约15分43秒，初始化约1.79秒；没有重新扫描原始盘口。

单独剖析2024-09-30：约2937万条原始记录，保留8.36万条候选快照。总43.55秒中，读取／解压29.02秒，筛选转换对齐等13.10秒，质量检查1.41秒，盘口指标计算0.033秒。读取阶段包括Arrow解压，不是纯磁盘时间；这条有界提取路径仍有读取和转换优化空间，NumPy计算本身不是主要耗时。
