# P0／P1 分钟性能验证

[使用指南](USAGE.md) · [优化范围](PERFORMANCE_PLAN.md) · [统计口径](../STATS.md)

本轮保留Python＋NumPy＋PyArrow、float64、顺序账户和既有交易规则。没有引入Numba、Polars、C++、降精度或StatsEvery账户并行。

## 最终改动

- 每日复用证券／bar索引，一次映射多个行情字段；公共DayCube形状仍是`[1, security, bar]`，显式构造连续的bar截面，不缓存未来特征。
- 保留mmap读取。命中已完整发布的缓存时跳过构建锁；缺失时仍锁内复查、写临时文件并原子rename，源版本检查不变。
- 日末把全部时点账户一起做统计汇总，仍按slot区分独立账户；保留旧单账户daily_curve作为兼容参考。首末事件的NaN不会被跳过，非有限诊断输入沿用旧求和口径。
- 同一天的账户事件合并后按最多65,536行写出；期末持仓也按该上限合批。因子值仍使用独立的factor_batch_rows，不累积整个回测历史。
- CSV文件句柄复用，每批flush、完成标记前关闭；Parquet分区完整写入后才rename为可见文件。失败时临时分区不会混入已完成的数据集。
- 图表只扫描所需列，指标仍使用完整数据。

一版“每个小账户分别做通用聚合”的尝试在局部对照中比原实现慢约三成，已从Git基线恢复单账户函数，再改为跨时点批量汇总；退化版本没有提交。源读取微测也未支持用缓冲Arrow或直接Parquet替换mmap，因此保留原读取方式。

## 比较方法

基线为01f679f的冻结生产包。使用同一解释器、库版本、输入、股票轴、因子、费用、输出开关和单线程数值库，分别启动新进程。两边先准备应用缓存，再交错运行A/B、B/A、A/B，各三轮；耗时取中位数，不用cProfile结果计算加速比。两边都启用相同的轻量阶段计时包装。

| 样本 | 30分钟 | 1分钟 |
|---|---|---|
| 日期 | 2023-01-03至01-31，16个交易日 | 2023-01-03至01-04，2个交易日 |
| 股票轴／分组 | 5,939／10 | 同左 |
| 模式／每日时点 | StatsEvery／8 | StatsEvery／240 |
| 预热 | 30个交易日 | 1个交易日 |
| 因子窗口 | 160／40根已完成bar | 同样160／40根；不是20／5个交易日 |
| 标签期限 | 40根采样bar | 同左 |
| 因子／每日持仓dump | 关闭 | 同左 |
| 账户、诊断、参考统计、CSV、JSON、PNG | 开启 | 开启 |

两种频率不是同一策略或同等历史长度，不能直接互比收益或用其中一类外推所有1分钟任务。每轮还核对所有输出表、记录数、非数值字段、数值和执行限制计数。比较允许既有float64舍入容差，不放宽alpha的livetest容差。

## 三轮暖缓存结果

| 样本 | 旧版中位秒 | 新版中位秒 | 耗时减少 | 加速比 | 旧版三轮范围 | 新版三轮范围 |
|---|---:|---:|---:|---:|---|---|
| 30分钟／16日 | 18.547 | 10.916 | 41.1% | 1.70× | 18.411–18.604 | 10.890–11.135 |
| 1分钟／2日 | 49.035 | 24.073 | 50.9% | 2.04× | 48.133–49.408 | 24.072–24.083 |

两种样本均超过第一批设定的20%端到端目标；这是上述固定配置的实测，不外推到任意因子数量、滚动窗口或多年任务。

| 样本 | 旧／新峰值RSS（MiB，三轮最大） | 旧／新Parquet文件数 | 旧／新Parquet体积（MiB） |
|---|---:|---:|---:|
| 30m | 353.1 / 360.8 | 230 / 111 | 4.12 / 2.67 |
| 1m | 1470.9 / 1489.0 | 734 / 48 | 51.88 / 38.45 |

峰值RSS小幅增加（约1%–2%），不宣称内存下降。按日／有界批次释放、float64和完整输出均保留；1分钟240套账户本身需要更多状态内存。文件数减少来自合批，不是少保存记录。

### 应用冷缓存

另用两份新应用缓存目录：旧版44.275秒、新版28.242秒，完整数值对照通过。仅一轮，作冷构建成本参考，不作为稳态加速结论；NAS／内核页缓存未清空。

三轮两种频率加冷缓存共7组完整输出对照全部PASS；本次实测所有有限数值最大绝对差为0，字段、记录数、非数值字段和账户约束计数一致。源报告还保留CPU时间、进程逻辑I/O及系统I/O计数；NFS物理计数可能无法代表实际网络传输量。

最终验收整组（含80项回归、真实f/p/c、预热、A/B与表对照）耗时12分10秒、CPU约7分4秒；cgroup峰值约2.1GiB、无swap。硬限制3核／6GiB、每5秒监控，未触发保护；结束MainPID=0、inactive，监控正常退出。此整组时间与单次回测时间含义不同。

## 正确性与故障验证

完整本机回归80项通过，包括float64小差异保留、串并行、1／5／30分钟PIT、真实新进程checkpoint、Every／Interval／Cohort兼容。新增专项覆盖乱序与稀疏行情、重复键、连续bar切片、并发冷缓存、暖缓存与版本更新、真实首末事件NaN、批次上限、活动CSV可读及失败Parquet分区隔离。

真实5分钟NAS数据的f／p／c分别6／2／3次比较全部PASS；检查的是生产alpha链路，不是完整账户断点续跑。

另外各做一次日频Every和5分钟StatsInterval的真实运行对照，全部表、记录数及执行计数一致。日频最大数值差为0；Interval汇总求和有最高约3.73e-9的末位差异，在既有容差内，交易事件与期末持仓相同。单轮耗时分别为9.23→4.55秒、17.33→12.13秒，仅作兼容性／明显退化检查，不替代上面的三轮性能结论。

## 复现与限制

先按工作区规则检查实际资源、设置输出与临时目录、配置硬限制，再运行以下工具。它们不会清空旧缓存；目录必须是新的外部产物目录。

```bash
python scripts/profile_backtest.py --config configs/readme_30m_5y.toml \
  --start 2023-01-03 --end 2023-01-31 \
  --profile --directory "$PROFILE_DIR"

# BASELINE_ROOT内需有指定旧提交导出的qsim包；代码快照放代码目录。
python scripts/benchmark_p1.py --baseline "$BASELINE_ROOT" \
  --directory "$BENCHMARK_DIR"

python scripts/compare_backtests.py "$OLD_RUN" "$NEW_RUN" \
  --output "$COMPARISON_JSON"
```

剖析脚本强制因子与库线程为1，默认单任务预算2048MiB，并保存失败报告、阶段独占／包含时间、版本和输出路径。它只测一个进程的生产调用；cProfile有额外开销。启动顺序与正常CLI一致，避免本机Conda／系统C++运行库混用；没有升级共享环境。

应用冷缓存使用两份新目录；不删除旧目录，不清系统页缓存，因此不声称NAS物理介质也完全冷。NAS和共享服务器负载会波动，报告保留每轮范围、CPU、RSS、I/O和文件数，而不是承诺固定加速比。

分区文件数会减少，但表名、字段和逻辑记录保留；不要依赖一个Parquet文件对应一个时点账户。checkpoint包含代码指纹，旧版检查点需用匹配旧代码恢复。需要回退时以pre-p1-20261030／01f679f为基线，撤回本轮提交，不重置或覆盖其他人的工作。

长窗口增量算法、公共表达式子树、Numba内核及更高并发属于第二批，未在本轮实施。
